## 本地构建结果

环境：Keil MDK 5.14、ARM Compiler 5.05 update 1 build 106、Keil.STM32G4xx_DFP.1.3.0。目标含 30 个 C 翻译单元、1 个启动汇编文件。CMSIS Core 依赖使用仓库随附头文件，工程未绑定外部 CMSIS RTE 组件版本。

| 项目 | 字节数 |
| --- | ---: |
| Code | 19,644 |
| RO-data | 5,080 |
| RW-data | 140 |
| ZI-data | 15,868 |
| Flash 负载估计：Code + RO + RW | 24,864 |
| 静态 RAM：RW + ZI | 16,008 |

静态 RAM 包含 `heap_4` 的 14 KiB 堆数组；任务栈从该堆分配，不能把任务栈声明空间再次加到静态 RAM 值上。上述数值不是运行时堆剩余量或栈峰值。

新生成的 `build/PF-MCS-freeRTOS.hex`：

- 文件大小：69,981 字节；Intel HEX 记录数：1,557；所有记录校验和有效。
- 实际写入字节：24,864；地址范围：`0x08000000`～`0x0800611F`，包含两端。
- 初始 SP：`0x20003E88`；复位向量：`0x080002AD`，Thumb 位有效且入口位于 Flash。
- SHA-256：`688cf61493e609c935145f00a4e7c6ee658cb033a3545b77cbb9fb42cb5dd78f`。
- 解码后的写入地址与字节内容与整理前保留的上板 HEX 一致。这支持本次移除虚拟分支、收敛依赖和修正文档没有改变该版本硬件固件内容；它不证明原始 HEX 曾完成上板验收。

构建记录包含全部 C/H/启动汇编/工程文件的内容哈希，计算时统一 CRLF 为 LF，以便在 Git 不同换行设置下核对源码身份。不同编译器或优化设置可能产生不同 HEX，应重新记录构建结果。

发布目录按源码仓库方式交付，不保留该 HEX 和 AXF；按照 README 构建后可重新生成。

## 软件算法验证方法

`tools/test_algorithms.py` 把当前 `Src/app.c` 直接包含进临时 C 测试程序。测试用采样值、按键电平和软件时间替代硬件输入；以有限次数执行周期任务。FreeRTOS、LCD 和 BSP 测试桩只存在于临时目录，不进入 Keil 工程。

本次在 Windows 主机使用 Zig 0.16.0 的 C 编译器前端运行，编译参数包含 `-std=c99 -O0 -Wall -Wextra -Werror`。GitHub 工作流提供 Linux 主机编译回归，远程检查结果以仓库 Actions 页面为准。

| 组别 | 断言数 | 覆盖内容 |
| --- | ---: | --- |
| 压力映射 | 13 | 零输入、四分之一/中点/满量程、超上限、非零零点、非法满量程零点 |
| 流量与积分 | 22 | 800/8000 Hz 边界与超频、余数保留、60 s 累计、累计上限饱和 |
| 控制 | 12 | 手动升降斜坡、12 s 软件时间、死区含端点、正反步进与占空比边界 |
| 告警 | 10 | 第 20/21 次边界、堵塞恢复、泄漏条件、严格不等号、LED 位组合 |
| UI 状态机 | 13 | 三页切换、暂存/提交、模式切换、1999/2000 ms 长按阈值、占空比编辑限幅 |
| 按键去抖 | 7 | 注入抖动后的单次按下/释放、事件时长、长按释放时长 |
| **合计** | **77** | **全部通过** |

主机测试不会执行 Cortex-M4 FreeRTOS 上下文切换、外设寄存器访问或实际 LCD 总线时序，因此不能用来证明任务最坏响应时间、优先级反转表现、ADC 精度、PWM 抖动或掉电恢复能力。
